# 평가

## 정답
정정신고 표지 "3. 정정사항" 표

| 항목 | 정정요구ㆍ명령 관련 여부 | 정정사유 | 정정 전 | 정정 후 |

- positive: "여/예" 행의 (회사, 연도, 항목). 입력은 정정 전 원본 사업보고서의 해당 섹션
- negative: 같은 기간 정정 없이 통과한 사업보고서의 같은 항목 + "부/아니오" 행(자진정정)
- hard negative: 통과 보고서 중 해당 항목이 짧거나 "해당사항 없음"인 것

## 지표
| 지표 | 정답 출처 | 계산 |
|---|---|---|
| 항목 단위 recall (주) | 표지 "여" 열 | 플래그한 여 행 / 전체 여 행. 항목별 집계 |
| 통과 보고서 100건당 오탐 (보조) | 정정 없는 사실 | 플래그한 negative 수 / negative 100건 |
| 근거 문단 적중률 (보조) | 표지 정정 전/후 열 | 근거가 가리킨 문단 ∩ 정정 후 바뀐 문단 ≠ ∅ |

전체 평균은 쓰지 않음. 항목(자기주식 / 소수주주권 / 공급계약 / 재무)별로 보고.

## baseline
1. 규칙: 섹션이 비었나, "해당사항 없음"인가, 첨부가 없나, 글자 수 N 미만인가. 하루 안에 제작
2. 무맥락 LLM: 섹션만 주고 "미흡한가"

## 단계별 비교
같은 정답에 대해 recall을 다시 잼

| 단계 | 방법 |
|---|---|
| 1 | 규칙 |
| 2 | 규칙 + LLM 판정 (대형 API, 상한) |
| 3 | 2 + 타사 통과 예시 검색 |
| 4 | 3을 로컬 7B 양자화 모델로 |

결과는 eval/results.csv에 한 줄씩 누적. 코드·프롬프트를 바꾼 PR은 이 줄을 반드시 포함.

## 사람 판정이 끼는 곳
근거 겹침 지표가 사람 눈과 맞는지 50건 2인 검증. 주 지표가 아니라 지표의 검증용.

## 누출 방지
- 같은 회사가 튜닝(2024년분)과 평가(2025년분) 양쪽에 있지 않도록 회사 단위 분리
- 평가는 해당 연도 점검 항목 기준으로만
