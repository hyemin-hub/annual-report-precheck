# 문제 정의 (한 페이지)

## 한 문장
상장사 공시담당자가 사업보고서를 제출하기 전에, 금감원이 점검하는 항목이 "채워져는 있지만 충분한지"를 스스로 판단할 기준이 없어 매년 100곳 넘게 제출 후 정정요구를 받음 → 초안의 해당 섹션을 읽고 정정요구 받을 항목을 근거와 함께 짚어주는 사내 배포용 사전 점검기

## 대상의 현재 상태
- 상장사 공시담당자가 사업보고서 작성·제출. 코스닥은 IR·공시 담당이 인사·총무 겸임이 흔함 (코스닥협회 2026.06)
- 금감원이 5월 점검 → 6월 미흡 통보 → 회사 [기재정정] 제출. 2025년분 점검 재무 221사, 자기주식 123사, 소각 234사, 제재 83사, 중대재해 24사 (금감원 2026.06.30)
- 2025.06~08 [기재정정] 사업보고서 348건 중 표지 파싱 109건의 102건이 정정요구 관련 (측정값)
- 정정요구 사유 55% "미흡·보완"(내용 부족), 23% "빈칸·누락" (122행 분류, 측정값)
- (가정) 회사 측 1건 소요 반나절~1일. 공시담당자 인터뷰로 확인 예정
- (가정) 연간 정정요구 비율 10~15%. 전수 수집 후 측정

## 입력 / 출력 / 소비자
- 입력: 제출 전 초안의 점검 항목 섹션 (I.4 자기주식, VI.3 주주총회·소수주주권·의사록, XI.1 공시내용 진행·단일판매공급계약, III 재무 일부) + 당해 수시공시 목록
- 출력: 항목별 정정요구 가능성 플래그 + 근거 한 줄 + 정정 후 통과한 타사 문단 예시
- 소비자: 상장사 공시담당자

## 성공 기준
- 주 지표 하나: 항목 단위 정정요구 recall. 정답 = 정정신고 표지 "정정요구ㆍ명령 관련 여부 = 여" 행
- 보조: 통과 보고서 100건당 오탐 수, 근거 문단 적중률(표지 정정 전/후 열과 겹침)
- 비교 대상: 규칙 체크리스트(빈칸·누락·첨부·길이), 무맥락 LLM

## constraint
- 공개 데이터만. OpenDART 일 20,000회
- 점검 항목은 매년 2월 예고, 연도별로 다름 → 평가셋을 연도별로 분리
- 운영 입력(초안)은 미공개 중요정보 → 외부 API 전송 불가 → 로컬 sLLM 또는 사내 배포
- (가정) 건당 API 비용 수백 원
- 평가 2025년분 / 튜닝 2024년분, 회사 단위 분리

## 하지 않을 것
- 빈칸·누락·첨부 누락 판정 (규칙 baseline 영역)
- 재무제표 수치 오류·XBRL 불일치 (회계사 영역)
- 점검 항목 밖 섹션
- 정정 문안 자동 작성
- 증권신고서 (같은 표지 구조, 1차 범위 밖)

## 알려진 한계
- 선택 편향: "여" 라벨은 금감원이 본 회사에서만 나옴 → negative에 미흡 섞임 → 오탐 과대평가. recall은 무관
- 라벨 노이즈: 표지 서식 상이로 152건 중 43건 파싱 실패 → 30건 수작업 대조 예정
- 사전학습 누출: 회사명 마스킹, 가능하면 2026년분 재평가
